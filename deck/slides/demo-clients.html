the same steps, three forms  —  a JSON test file, and Mobium's two agentic clients

the test file  ·  one JSON document, run by mobium test, the runner built into the binary

{"accessibility": {"setting": "reduce_motion", "value": "${reduce_motion}"}}

{"tap": "label=Motion Demo"}

{"wait_for": {"target": "testid=reduceMotion", "condition": "text", ...}}

the CLI  ·  one command per step

$ mobium accessibility reduce_motion on

$ mobium tap "label=Motion Demo"

$ mobium wait testid=reduceMotion --for text --text "reduceMotion=true" --exact

MCP  ·  JSON-RPC 2.0 requests to mobium mcp, one message per line on stdio — what an AI agent sends

{"jsonrpc": "2.0", "id": 4, "method": "tools/call", "params": {"name": "app_accessibility", ...}}

{"jsonrpc": "2.0", "id": 5, "method": "tools/call", "params": {"name": "app_tap", ...}}

{"jsonrpc": "2.0", "id": 6, "method": "tools/call", "params": {"name": "app_wait_for", ...}}

The first three of the test's eleven steps, in three forms. The test file is one JSON document — not newline-delimited — and mobium test, the runner built into the binary, reads it and sends each step as a tool call. The two clients are the CLI, one command per step, and MCP: JSON-RPC 2.0 requests to mobium mcp, one message per line on stdin and stdout, which is what an AI agent sends. demo/motion-cli.sh is checked against the test file before it runs; demo/motion-mcp.py sends the file's steps as they are. Same tools underneath all three.
